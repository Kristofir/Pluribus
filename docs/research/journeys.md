# User journeys

Working document for mapping concrete user situations, current workarounds, and
possible product experiences. Journeys are hypotheses until supported by evidence.

See [Product proposition and user experience](product.md) for the broader framing.

## Approach

Start with what someone is trying to accomplish and how they do it today. Map the
proposed experience separately so we do not mistake a feature idea for a user need.

## Candidate journey: collaboratively respond to an email

**Status:** Illustrative hypothesis from our discussion, not a validated or chosen
primary journey. The user group and concrete situation remain undefined.

**Trigger:** Someone receives an email that would benefit from another person's
input.

**Desired outcome:** Produce a response informed by the relevant information and
the collaborators' contributions.

### Possible sequence

1. Read the message and identify where help is needed.
2. Invite another person to contribute.
3. Gather relevant information and discuss it together.
4. Develop and edit a response.
5. Decide it is ready and send it.
6. Continue with the earlier context available when a reply arrives.

### Still to map

- A concrete example and the people involved.
- How they accomplish this today and where the actual difficulty occurs.
- Whether a canvas helps this task or adds unnecessary work.
- What belongs in private collaboration versus the outgoing response.
- Whether this is frequent and important enough to justify a dedicated product.
